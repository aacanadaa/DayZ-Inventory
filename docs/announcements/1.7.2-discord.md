## Long version — `#dayz-inventory` / `#general`

> ## DayZ Inventory 1.7.2
>
> **Forge is back, and the whole matrix publishes itself.**
>
> The mod is unchanged. What changed is everything around it.
>
> **One source tree, seven jars.** 26.2, 1.21.11 and 1.21.1 each build for Fabric and NeoForge, and
> 1.21.1 also builds for Forge — all from the same codebase, with the version differences marked
> inline where they happen. Forge stopped at 1.20.x, so 1.21.1 is the newest version it can be built
> for at all.
>
> **Forge needed real work.** It was still on the 1.20.1-era `SimpleChannel` networking stack, which
> no longer exists; it now uses the same typed-payload model as the other two loaders.
>
> **Publishing is automated.** Every jar goes up with its own Minecraft version and loader tags, read
> from the build rather than typed per release, so nothing can be filed under the wrong version.
>
> ### If you downloaded 1.7.1 on Fabric for 1.21.1 or 1.21.11
>
> **Replace it.** That file was Loom's *development* jar by mistake — it will not load in a normal
> game. 1.7.2 is correct. Every NeoForge file, every Forge file, and the 26.2 Fabric file were fine,
> and the jars on the GitHub releases were always correct.
>
> ### Downloads
>
> - Modrinth — https://modrinth.com/mod/dayz-inventory/versions
> - CurseForge — https://www.curseforge.com/minecraft/mc-mods/dayz-inventory/files
> - GitHub Release (all seven jars) — https://github.com/aacanadaa/DayZ-Inventory/releases/tag/v1.7.2
>

> | 1.21.11 | ✅ | ✅ | — | 21 |
> | 1.21.1 | ✅ | ✅ | ✅ | 21 |
>
> **1.20.1 is not going anywhere.** The 1.20.1 files (Fabric and Forge) are still published and still
> work. They come from the older per-version build and haven't been folded into the unified tree yet.
>
> Still want [DayZ Hotbar](https://modrinth.com/mod/dayz-hotbar) alongside it — they're built as a pair.
