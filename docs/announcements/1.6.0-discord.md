## Long version — `#dayz-inventory` / `#general`

> ## DayZ Inventory 1.6.0
>
> **The mod is unchanged. How it is built is not.**
>
> Until now every Minecraft version lived on its own Git branch — `main` for 1.20.1, plus `1.21.1`,
> `1.21.11` and `26.2`. Every fix had to be merged into all of them and built four times. This
> release replaces that with a single source tree that builds **1.21.1, 1.21.11 and 26.2 for both
> Fabric and NeoForge**, with the version differences marked inline in the code where they belong.
>
> The Vicinity grid, Proximity Scanner, 2x2 crafting, the 2.0x Hands slot, drag-to-equip and every
> optional integration (JEI / REI / EMI, Curios, Trinkets) behave exactly as before.
>
> **Downloads**
> - Modrinth — https://modrinth.com/mod/dayz-inventory/versions
> - CurseForge — https://www.curseforge.com/minecraft/mc-mods/dayz-inventory/files
> - GitHub Release (all six jars) — https://github.com/aacanadaa/DayZ-Inventory/releases/tag/v1.6.0
>
> | Minecraft | Fabric | NeoForge | Java |
> | :--- | :---: | :---: | :---: |
> | 26.2 | ✅ | ✅ | 25 |
> | 1.21.11 | ✅ | ✅ | 21 |
> | 1.21.1 | ✅ | ✅ | 21 |
>
> **1.20.1 is not going anywhere.** The 1.20.1 files (Fabric and Forge) are still published and still
> work. They come from the older per-version build and haven't been folded into the unified tree yet —
> 1.20.1 predates the 1.20.5 networking rewrite, so it needs real port work, not a rebuild.
>
> Full write-up: https://github.com/aacanadaa/DayZ-Inventory/releases/tag/v1.6.0
> Still want [DayZ Hotbar](https://modrinth.com/mod/dayz-hotbar) alongside it — they're built as a pair.

## Blocker: the release is not on Modrinth or CurseForge yet

CI ran the publish job on the `v1.6.0` tag and it stopped with:

```
##[error]No Modrinth token. Add a repository secret named MODRINTH_TOKEN.
##[error]No CurseForge token. Add a repository secret named CURSEFORGE_API_KEY.
```

The repository has no publishing secrets — the tag log shows `MODRINTH_TOKEN: ` and
`CURSEFORGE_API_KEY: ` expanding to empty. Add both under
**Settings → Secrets and variables → Actions**, then either push the tag again or run:

```bash
MODRINTH_TOKEN=... CURSEFORGE_API_KEY=... ./gradlew publishAll -Ppublish.dry_run=false
```

The task is wired and dry-run clean for all six nodes; only the credentials are missing. The
GitHub Release itself did go out, so the jars are downloadable from the link above in the meantime.
